# 车机体验优化第二轮：渲染 / 触控 / 重连 / 音量 OSD / 音频 / HUD

日期：2026-10-15 · 状态：已确认（视觉延续 [UI Refresh 设计](2026-10-15-ui-refresh-design.md)，白底 + 彩虹点缀）

## 目标

解决上车实测四个痛点：画面卡顿/跟手差、触控漏点、断连后体验差、音量调节无反馈；并让「卡不卡」可量化（HUD 度量），为后续 WebRTC 决策提供数据。

## 非目标

- 不改 Rust/TS 服务端、不改协议（触控/音频/视频消息格式不变）
- 不做 WebRTC 直通（WheelPlay 二期）：等本轮 HUD 数据证明存在网络层丢包再立项
- 不新增设置项

## 改动文件

仅 `native/Engine/webclient.html`。

## 设计

### 1. 渲染追帧丢弃（永远画最新帧）

- 现状：解码回调同步 `ctx2d.drawImage(frame)`，解码追帧时旧帧逐张画完，肉眼可见快进式卡顿。
- 改法：解码 output 回调只更新 `pendingFrame`（新帧到时 close 旧 pending），独立 rAF 渲染循环每 vsync 取最新帧绘制。追帧时中间帧丢弃。
- HUD 增加「丢帧 N」= 解码帧数 − 实画帧数。

### 2. 触控增强

- `getBoundingClientRect` 结果按元素尺寸缓存，resize / 安全边距变更时失效重算；pointermove 不再每事件重算布局。
- `pointerdown` 保持立即直发；move 维持 rAF 合帧（现状已好，不回退）。
- 确认视频元素 CSS `touch-action:none` 覆盖，防止浏览器手势抢事件导致漏点。

### 3. 重连健壮化

- 指数退避：2s → 5s → 10s 封顶，/touch 与 /h264 两条 WS 同规则；连接成功后重置。
- `visibilitychange`（回前台）与 `online` 事件触发立即重连并重置退避。
- 断连横幅分级：显示「连接已断开 · 正在重连…（第 N 次）」；重连成功横幅淡出 + 底部小 toast「已重新连接」2s 自动消失。
- 音频与触控同走 /touch WS，重连即恢复，无额外处理。

### 4. 音量 OSD

- 触发：面板 4 条音量滑杆 input；新增键盘快捷键 `-` / `=` 调总音量（±5%）。
- 视觉：屏幕下方居中彩虹渐变胶囊（同设计 token），音量图标 + 大字百分比 + 细进度条；持续显示时刷新，停止 2s 淡出（复用 hint 淡出风格）。纯 UI。

### 5. HUD 增强：RTT

- 客户端每 20s 发 `{t:'ping'}`，服务端已回 `{t:'pong'}`（零服务端改动）：记录发送→回包时间差，取最近 5 次平均显示「延迟 Nms」。

### 6. 音频全流自适应缓冲

- 现状：仅媒体流有自适应 jitter（0.35s 起、欠载 +0.1s、20s 健康 −20ms、地板 0.3s、落后 >0.25s 跳到实时）；导航/通话固定 60ms 起播，弱网碎音。
- 改法：全流走 `jitterFor`，按流类型分起步值：媒体 0.35s / 导航 0.15s / 通话 0.06s；加深、回落、跳实时规则沿用，回落地板 0.3s 仅对媒体生效，导航地板 0.15s、通话地板 0.06s。
- HUD 增加「音频欠载 N」计数（每次 underrun +1，会话累计）。

## 边界情况

- pendingFrame：切换 MJPEG/WebCodecs、decoder 重配置时清空 pending，避免旧帧闪现。
- RTT：pong 丢失不惩罚，仅更新有回包的样本；HUD 显示 `—` 直至首个样本。
- 音量 OSD 与断连横幅、设置面板互不遮挡（OSD 置底部居中，z-index 低于面板）。
- 重连 toast 与 hint 共存时后到者覆盖。
- 通话流延迟敏感：jitter 起步与地板都是 0.06s，欠载加深后同样回落。

## 测试

- node 提取 JS 语法校验。
- 桌面 Chrome：断网/恢复模拟退避与 toast；音量滑杆/键盘触发 OSD；HUD 出现 RTT 与两个计数。
- 车机 Android 浏览器 2.5K：进隧道断连 → 横幅计数 → 恢复自动重连；导航语音弱网不碎；触控连续滑动不掉点；调音量出现彩虹 OSD。
